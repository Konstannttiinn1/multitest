# Multitest

Интерактивный bash-скрипт для диагностики и тестирования Linux-серверов. Объединяет популярные инструменты проверки в одном меню.

## Быстрый старт

### Единственная рекомендуемая команда установки

Используйте основной репозиторий `Konstannttiinn1/multitest`. Команды со ссылкой
на `saveksme/multitest` устанавливают исходную версию без надёжного применения
CAKE к активному сетевому интерфейсу.

```bash
curl -sL https://raw.githubusercontent.com/Konstannttiinn1/multitest/master/multitest.sh -o /usr/local/bin/multitest && chmod +x /usr/local/bin/multitest && echo "Установлено! Запуск: multitest"
```

После установки проверьте версию:

```bash
multitest --version
```

Ожидаемый результат для этой версии: `Multitest 1.5`.

### Другие варианты

**Одноразовый запуск без установки:**

```bash
bash <(curl -sL https://raw.githubusercontent.com/Konstannttiinn1/multitest/master/multitest.sh)
```

После установки скрипт доступен из любого места:

```bash
multitest
```

### Утилиты

| # | Название | Описание |
|---|----------|----------|
| 1 | BBR + CAKE | Включение TCP BBR и фактическое применение CAKE к интерфейсам с маршрутом по умолчанию |
| 2 | Выключить IPv6 | Отключение IPv6 через sysctl |
| 3 | Fail2Ban | Установка и защита SSH: 5 ошибок за 10 минут блокируют IP на 12 часов |
| 4 | Статус | Проверка реального состояния BBR, CAKE на каждом интерфейсе и jail `sshd` |
| 5 | Шейпер Umka | Проверка ноды и автоматическая подготовка или включение шейпера |

### Шейпер Umka

На Ubuntu 24.04 x86_64 с systemd, ядром от 5.18 и доступным BTF запусти
от root **Утилиты → 5** или выполни:

```bash
multitest --shaper
```

Для разового запуска без установки Multitest:

```bash
curl -fsSLo /root/umka-shaper.sh https://raw.githubusercontent.com/Konstannttiinn1/multitest/278ac577db3fb0885fb37c5ba17b0841bbceddc6/umka-shaper.sh &&
  printf '%s  %s\n' '5ce1d5578c643d9c4d0029c662c88900ffa77e7feaea1ea64c552c1ecca300ea' /root/umka-shaper.sh | sha256sum --check - &&
  bash /root/umka-shaper.sh
```

Скрипт пишет отчёт, проверяет маршруты, очереди и слушающие порты. При одном
интерфейсе по умолчанию и одном внешнем порте `rw-core` / `xray` он установит
и включит шейпер. На пустой ноде со свободным портом 443 подготовит его под
443. После запуска VPN повтори команду: она активирует готовый пакет.
На работающем шейпере повторный запуск покажет службу и фильтры.

Правило действует на **внешний IP клиента**: свыше 100 Мбит/с в любом
направлении 10 минут подряд → 30 Мбит/с отдельно в обе стороны на 40 минут.
По истечении этого времени ограничение снимается автоматически.

Для нестандартной схемы укажи внешний интерфейс и нужные порты явно:

```bash
multitest --shaper --interface eth0 --ports 443,8443
multitest --shaper --interface eth0 --ports 443 --prepare-only
multitest --shaper check
```

За обратным прокси указывай публичный порт. Шейпер учитывает весь трафик
выбранного порта; если на нём одновременно VPN и сайт, правило охватывает
оба. Интерфейс и порты уже установленного шейпера сохраняются при повторном
запуске, поэтому нестандартный порт лучше указать при первой подготовке.

При активной или включённой службе `multitest-cake.service` переход на Umka
остановится: обе службы управляют очередями. Для перехода сначала отключи
автоприменение CAKE командой `systemctl disable --now multitest-cake.service`.
Текущие очереди сохраняются перед установкой. Статус `ACTIVE` и наличие
фильтров подтверждают запуск; фактический предел и снятие ограничения
проверяются реальным VPN-трафиком на ноде.

Состояние: `umka-shaper status`. Остановка с отключением автозапуска:

```bash
systemctl disable --now umka-traffic-shaper.service
umka-shaper stop
```

### Чем новая проверка CAKE отличается от старой

Значение `net.core.default_qdisc=cake` само по себе не означает, что CAKE уже
работает на активном сетевом интерфейсе. Утилита теперь:

1. Находит интерфейсы по IPv4/IPv6-маршрутам по умолчанию, не полагаясь на имя
   вроде `eth0`, `ens3` или `enp1s0`.
2. Выполняет `tc qdisc replace dev <интерфейс> root cake triple-isolate`.
3. Проверяет, что в выводе `tc qdisc show` действительно присутствует
   `qdisc cake ... root`.
4. На системах с systemd устанавливает `multitest-cake.service`, чтобы повторно
   применить и проверить CAKE после поднятия сети при перезагрузке.
5. Сохраняет параметры в `zz-multitest-bbr-cake.conf`, который загружается после
   типового `99-sysctl.conf` и не позволяет поздней настройке `qdisc=fq`
   незаметно отменить CAKE.
6. После успешной установки предлагает перезагрузить VPS прямо из меню:
   `Перезагрузить сервер сейчас? [y/N]`.

CAKE применяется в режиме `triple-isolate`. Сервис автозапуска до 30 секунд ждёт
появления маршрута по умолчанию, поэтому не привязан к именам `eth0`, `ens3` или
порядку поднятия сети.

Перезагрузка не обязательна для немедленного запуска: CAKE применяется сразу.
Она нужна для контрольной проверки, что настройки и `multitest-cake.service`
правильно восстановятся после старта VPS. Ответ `y` запускает перезагрузку,
Enter или `N` оставляет сервер работающим и напоминает команду `reboot`.

Если хотя бы одна из проверок не прошла, скрипт не сообщает об успехе и выводит
красный статус проблемного компонента.

Для редких схем маршрутизации интерфейс можно указать явно перед запуском,
например: `MULTITEST_NET_IFACE=ens3 multitest`.

### Настройки Fail2Ban

Создаётся отдельный файл `/etc/fail2ban/jail.d/sshd-multitest.local`. SSH-порт
определяется через итоговую конфигурацию `sshd`, поэтому поддерживается и
нестандартный порт. Перед перезапуском выполняется `fail2ban-client -t`, после —
проверка активного jail `sshd`.

## Зависимости

Скрипт автоматически установит недостающие пакеты:

- `curl`
- `wget`
- `sysbench`
- `iperf3`
- `iproute2`/`iproute` (для `ip` и `tc`)
- `kmod`
- `fail2ban` (при выборе соответствующего пункта)

Поддерживаемые пакетные менеджеры: `apt`, `dnf`, `yum`, `apk`, `pacman`.

## Требования

- Linux (Debian/Ubuntu, CentOS/RHEL, Fedora, Alpine, Arch)
- Права root (для установки пакетов и утилит)
- Bash 4+
